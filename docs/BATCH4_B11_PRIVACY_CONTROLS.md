# Malo 1.1｜B11 Cloud Backup 删除：隐私与用户控制说明

## 已实现的用户控制

Malo 现在明确区分以下三个动作：

1. **关闭云端备份**：停止新的自动备份和自动恢复，已存在的云端备份继续保留。
2. **删除云端备份**：删除当前微信身份对应的全部云端备份；本机日记、计划、本地心声和自定义急救卡不受影响；自动云端备份同时关闭。
3. **清空本机数据**：删除本设备上的 Malo 数据，云端备份不删除，并继续使用 `recoverySuppressed` 防止自动恢复。

删除云端备份后，只有用户再次主动点击“开启云端备份”，服务端才会重新允许保存，并以当前本地核心数据创建新备份。普通 app launch、`onHide`、自动重试或 `saveBackup` 都不能自行重新开启。

## 数据范围

B11 没有增加新的个人信息类型，没有改变 Cloud Backup snapshot 的内容，也没有改变 `schemaVersion: 1`。删除目标仍是当前服务端 OPENID 所属的 `user_backups`；客户端不能提交 owner、OPENID、userId 或 backupId 来选择删除对象。

B11 不删除：

- 当前设备上的 Malo 本地数据
- `users` 身份记录
- 用户主动递出的试用反馈及其独立云端记录

`users.backupMode` 会变为 `disabled`，并保留 consent/control metadata，用于执行“删除后不再自动上传”的用户选择。

## 保存期限与删除表述

小程序对外说明应与实际 Cloud Database、云函数日志、平台运维备份和法定留存规则一致：

- 对 `user_backups`，产品语义是保留至用户主动删除、服务终止或已公开的保存期限届满，以较早者或适用规则为准。
- UI 只有在 owner backup rows 已复查为零后才显示删除成功；部分失败时保持自动备份关闭并提示重试。
- 若底层平台或运维备份存在延迟清除窗口，正式隐私文本必须如实披露，不能承诺超出实际能力的“即时、不可恢复删除”。

## 微信公众平台人工复核

B11 不新增微信后台“个人信息类型”。发布前由小程序管理员人工复核现有《用户隐私保护指引》，重点确认：

- 云端保存核心记录的用途仍描述为备份/恢复，而不是实时多设备同步。
- 保存期限与实际策略一致。
- 用户删除途径写明：小程序内“隐私与安全说明 → 云端备份 → 管理云备份 → 删除云端备份”。
- 关闭备份、删除云端备份、清空本机数据的差异与小程序内文案一致。
- 如后台当前用途、期限或权利行使路径与上述实现不一致，应更新并按平台流程提交；如果完全一致，则不新增信息类型。
